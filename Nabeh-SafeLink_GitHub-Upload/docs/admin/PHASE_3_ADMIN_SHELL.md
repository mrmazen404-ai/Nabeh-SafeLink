# المرحلة الثالثة — Admin Shell والواجهات المحمية

## ما تم بناؤه

تم تحويل واجهة Admin من شاشة جلسة أولية إلى Shell إداري فعلي يعمل فوق المصادقة والجلسات وRBAC في المرحلة الثانية.

### التخطيط

- Sidebar ثابت للشاشات الكبيرة.
- Bottom Navigation للهاتف.
- قائمة جانبية قابلة للفتح والإغلاق على الشاشات الصغيرة.
- Scrim لإغلاق القائمة خارجها.
- Header ثابت مع اسم الوحدة الحالية.
- زر RTL/LTR.
- زر Dark/Light Mode.
- هوية بصرية متسقة مع Welcome وSafeLink.

### حماية المسارات

- لا يظهر Shell دون Access Token وRefresh Token.
- يتم استدعاء `/auth/me` قبل عرض الواجهة الداخلية.
- يتحقق Backend من الجلسة وRLS وRBAC.
- عند انتهاء الجلسة يتم مسح Tokens وإعادة المستخدم إلى شاشة الدخول.
- الوحدات المرئية تعتمد على Permission Codes القادمة من `/auth/me`.
- حماية الواجهة ليست بديلاً عن حماية Backend؛ المسارات نفسها محمية في FastAPI.

### الوحدات الموجودة في Shell

- Dashboard فعلي مع حالة الجلسة والدور و2FA وإجراءات سريعة.
- Sessions متصل بـ `/api/v1/admin/sessions`.
- Audit Center متصل بـ `/api/v1/admin/audit-logs`.
- Users وScans وStatistics لها شاشات محمية وحالات واضحة، وسيتم توصيلها بالـ API في مراحلها الوظيفية.
- Profile له حالة محمية ضمن Shell.

### حالات الواجهة

- Loading عند استعادة الجلسة.
- Loading للبيانات.
- Empty State.
- Error State.
- Session Expired.
- Responsive على الهاتف والتابلت وسطح المكتب.
- Reduced Motion عند طلب النظام.

## الفحص البصري

تم بناء نسخة الإنتاج والتقاط الواجهة على:

- `390×844` للهاتف.
- `1440×900` لسطح المكتب.

النتيجة: شاشة الدخول متجاوبة، دون تمرير أفقي، والهوية البصرية مستقرة في المقاسين.
