# المرحلة الخامسة — إدارة المستخدمين والصلاحيات التشغيلية

## النطاق المنفذ

تم تنفيذ إدارة المستخدمين على جدول `custom_users` الحقيقي في Supabase، مع منع كشف `password_hash` وOTP وأي أسرار.

### القراءة

```text
GET /api/v1/admin/users
GET /api/v1/admin/users/{user_id}
```

مسار القائمة يدعم:

- Pagination عبر `limit` و`offset`.
- بحث بالبريد أو الاسم.
- فلترة حسب `ACTIVE`, `SUSPENDED`, `DELETED`.
- إجمالي النتائج داخل `meta.total`.
- حقول آمنة فقط.

مسار التفاصيل يعرض الحقول الآمنة وعدد الفحوصات وعدد البلاغات للمستخدم.

### التعديل التشغيلي

```text
PATCH /api/v1/admin/users/{user_id}/status
```

يقبل فقط:

```json
{
  "status": "ACTIVE | SUSPENDED",
  "reason": "سبب واضح للتغيير"
}
```

قواعد التنفيذ:

- لا يمكن تغيير حالة مستخدم `DELETED`.
- السبب إلزامي وطوله بين 3 و500 حرف.
- العملية تحتاج `users.manage`.
- القراءة تحتاج `users.read`.
- كل تغيير يكتب Audit Event باسم `ADMIN_USER_STATUS_CHANGED`.
- يسجل Audit القيمة السابقة والقيمة الجديدة والسبب و`target_user_id`.

## الصلاحيات

| الدور | قراءة المستخدمين | تغيير الحالة |
|---|---:|---:|
| `SUPERVISOR` | نعم | لا |
| `ADMIN` | نعم | نعم |
| `SUPER_ADMIN` | نعم | نعم |

الصلاحيات مفروضة في Backend، وإخفاء الأزرار في الواجهة ليس طبقة الحماية الوحيدة.

## الواجهة

تم ربط صفحة المستخدمين بـ API حقيقي وتشمل:

- بحث.
- فلتر الحالة.
- Pagination.
- عرض البريد والاسم والدور والحالة وآخر دخول.
- زر إيقاف/تفعيل.
- طلب سبب العملية.
- رسائل Loading وError وEmpty.
- تصميم متجاوب للهواتف والشاشات الكبيرة.

## الخصوصية

لا تعرض القائمة أو التفاصيل:

- `password_hash`.
- رموز OTP.
- Recovery Codes.
- Tokens.
- أسرار المصادقة.
